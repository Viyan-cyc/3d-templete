# AI 设计生成规则

适用于 GTS PC 端界面设计、生成、修改和审查；视觉与组件基础版本为 GTS 2.2。本文件保留原 Skill 中直接约束设计表达的规则。

## 使用流程

1. 确定页面场景、组件与密度。默认使用本包统一 GTS 颜色，不询问配色体系，也不加载其他颜色表。
2. 创建或修改代码时核对实际组件库；已确认且有效的配置直接复用。注册、样式与最小真实组件运行验证通过后再搭建完整页面。纯规范查询不要求配置组件库。
3. 阅读 [视觉品质](<视觉品质.md>)，确定信息层级与视觉边界。
4. 阅读 [页面布局](<页面布局.md>) 和 [设计系统](<../样式Token/设计系统.md>)，确定画布、栅格、密度和对应 Token。
5. 从 [组件索引](<../组件规范/组件索引.md>) 读取相关组件；复合组件同时查阅内部子组件。
6. 结合 [响应式与无障碍](<响应式与无障碍.md>)、键盘、国际化及内容状态规则完成实现，逐项检查“不要”。

## 核心规则

- 页面只使用本包统一 GTS 颜色 Token，不保留其他颜色表、旧 Token 别名或隐式 fallback；组件、示例与库主题均按当前语义表映射。

- 按组件部位、语义和状态选择 Token；底层数值集中在主题或样式配置层，通过 Token 或组件属性调用，不以局部硬编码覆盖已有定义。
- 保留 Token 的名称、大小写和单位。文档中的 `*` 表示名称系列，使用前展开为参数表内实际存在的 Token。
- 默认浅色 UI，代码区按专用浅／深配色表使用；完整深色 UI 参数未定义时不自行推导。常规／紧凑间距分别按表取值，不等比缩放。
- 填充、文字、消息背景和标签背景分别选色。区分透明叠加值与已给定的合成色，不将背景透明度应用到整个组件。
- 组件内间距包含边框宽度，单侧 `padding + border-width` 等于目标间距；控件宽高不随间距密度自动等比缩放。
- 字号与行高成对使用；圆角和投影按组件具体部位选择，预留档位不作为默认值。
- 同类组件的状态映射保持一致。按实际能力提供默认、悬停、按下、聚焦、选中、禁用、加载或错误状态；禁用时停止交互，加载时避免重复提交。
- 保留 GTS 各组件的适用差异。命令集合使用下拉菜单，层级数据选择使用级联选择器；两者英文名均为 Dropdown，检索时使用完整中文组件名。
- 布局与组件文档未规定的尺寸或行为，采用用户要求与项目约定；不将推测值、其他设计体系的规则或框架类名写成 GTS 既有规范。

## 规则适用与冲突处理

- 用户明确指定的范围和要求优先；与本规范不一致时，指出具体差异，不将例外表述为 GTS 标准。
- Design System 中的当前 GTS 颜色表是颜色值的唯一依据；组件文档决定其用途和状态，旧项目定义或组件库默认值不能覆盖它。
- 组件文档决定具体用途、结构、行为及部位参数；Design System 提供通用视觉规则和 Token 定义。具体场景规则优先于通用场景规则，但不改变同名 Token 的底层值。
- 品牌与视觉品质用于整体判断，不覆盖具体组件和 Token 规则；响应式与国际化调整遵循组件行为，无障碍要求在对应交互中落实。
- 未覆盖的事项沿用项目约定；影响结果的关键参数缺失或同一条件下存在无法消解的冲突时，明确缺口，不自行补造规范。

## 任务输出

- **界面生成或修改**：按用户要求交付设计或实现，落实相关组件规则与 Token，不扩展无关页面或功能。
- **规范审查**：定位具体部位，列出违反的规则和可执行的修正建议；区分已确认问题与缺少信息而无法判断的项目。
- **组件规范编写**：每个组件独立成文，保留用途、结构、规则；按需增加类型、交互状态和视觉参数，最后列出具体的“不要”。沿用现有分类和命名，不重复维护 Token 数值表。

## 完成检查

- 组件用途、信息层级及操作归属与场景匹配。
- 所用 Token 均存在，主题、密度、颜色用途和组件部位对应正确；颜色绑定与实际页面均使用当前参数表，浮层、状态、图表与代码区无表外或失效引用。
- 相关交互状态可用，错误、禁用和加载行为与视觉表现一致。
- 页面任务检查视觉层级、目标视口、键盘焦点与必要语义；涉及多语言时检查长文案及格式。
- 逐项检查所用组件末尾的“不要”；只对已检查的范围声明符合规范。

- 页面代码任务检查真实库调用、适配映射和配置有效性；未接入组件库的原型需明确标注。

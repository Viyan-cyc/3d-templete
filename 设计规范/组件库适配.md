# 组件库适配

## 实现与规范

- 页面复用用户选择的真实组件库或项目封装，API 以实际代码和文档为准。
- 已选择组件库时，不自行退回无库 HTML；安装、路径检查或 import 字符串不能替代真实组件渲染与交互验证。
- 页面语言、组件样式和状态需完成配置。Sweet UI 的 `zh_CN`、`light` 仅为中文浅色验证示例；正式页面按项目语言和本包 GTS Token 执行。
- Element Plus 通过当前版本支持的主题接口接入 GTS Token；保留项目已采用的全量或按需导入方案，并核对实际组件样式是否加载。

## 组件与 GTS 的衔接

在项目 `.gts/frontend-adapter.md` 记录本次实际用到的映射，不复制整套规范或另维护 Token 数值表：

| 内容 | 必须确认的信息 |
| --- | --- |
| 组件 | GTS 组件名称 → 实际 import 路径／导出名称 → 属性、事件、插槽；附库内证据位置 |
| 状态 | GTS 状态 → 库的状态属性与事件；包括禁用、加载、校验错误、聚焦等适用状态 |
| 主题 | GTS Token 名称 → 库的主题变量／CSS 变量／适配样式位置；数值读取现有 Design System |
| 差异 | 不支持的结构、状态或样式，以及最小封装位置、待确认事项 |
| 验证 | 实际构建、交互与视觉检查范围；未验证部分明确列出 |

已对接的组件，页面代码必须导入并复用实际组件库或项目已有封装；不得用外观近似的原生元素替换后声称已对接。优先使用库支持的主题接口，其次在项目中集中封装适配；确实没有对应能力时，按 GTS 规则补充必要组件并记录缺口。

组件库提供实现，规范文档决定视觉与使用规则。页面颜色默认使用 [GTS 颜色](<../样式Token/设计系统.md#colors>)，不询问配色体系；库默认主题必须适配到本包 Token，不能作为缺失值的 fallback。保留现有 Token 名称、大小写、数值、主题、密度和语义；适配层做映射，不把库默认色值反写为 GTS 标准。不编辑第三方库源码或 `node_modules`，不在业务页面散布重复覆盖样式。

## 交付检查

- 真实依赖已解析，组件导入、属性、事件来自实际库；不得伪造公司 API。
- 交付页面工程源码、依赖声明及对应锁文件、主题适配和实际启动／构建命令。组件调用须能在该工程中解析；未接通的业务接口和未完成的验证单独说明，不以静态 HTML 冒充已接入的工程代码。
- 使用项目现有检查命令验证本次相关构建与交互；安装脚本和命令先按项目规则核对。
- 检查默认、悬停、按下、聚焦、禁用、加载及业务需要的其他状态，对照 GTS 的尺寸、间距、字体、色彩和层级。
- 组件库接入不能保证像素级一致；只有实际渲染检查过的范围才能声明还原情况。

# 响应式与无障碍

适用于 GTS PC 端页面及组件。视觉参数遵循 [Design System](<../样式Token/设计系统.md>)，具体行为遵循 [组件规范](<../组件规范/组件规则.md>)。

## 响应式与密度

### 适配范围

- PC 端为主要适配范围，按项目目标视口和容器宽度确定断点，兼顾窗口缩小与浏览器缩放。
- 平板和手机是否完整适配由项目范围确定；空间不足时保留关键内容、主操作及清晰的访问路径。
- 断点依据内容是否拥挤、溢出或难以操作确定，不仅按设备名称判断。
- 默认画布1440px；Console／作业／数据页面为24列流式栅格，不设统一内容最大宽度；Portal为12列固定栅格、内容最大1280px。常规槽宽16px、外边距20px；紧凑为8px、12px，完整公式与侧栏见 [画布与布局](<页面布局.md>)。
- 1280／1680／1920px 为重点断点检查值；1024px检查窄桌面；缩放按实际 CSS 视口处理。旧版1920／rem方案见 [兼容配置](<兼容与迁移.md#legacy-layout>)。

### 密度配置

- 常规与紧凑间距使用同名 `space-size-*` Token 的对应值，不按视口比例缩放。
- 控件高度、字号、行高和圆角各自按组件及 Token 配置，不随间距整体等比变化。
- 使用 rem 等实现单位时，保持实际尺寸与所选配置一致，不通过改变根字号生成额外的密度方案。
- 同一容器内保持密度一致，不能为了塞入内容随意压缩个别控件。

### 页面适配

- 窄屏优先保留标题、核心数据、主要操作、筛选入口及内容主体。
- 表格保留关键列与操作入口；次要内容可通过列配置、详情展开或横向滚动访问。
- 图表可改为纵向排列，优先展示主图；保留可读的坐标轴、图例和数据标签。
- 多列表单在空间不足时改为单列，标签、帮助文字和错误信息保持相邻。
- 侧栏可折叠，但保留当前模块、层级和子菜单入口。
- 工具栏可将低频操作和筛选条件收纳至菜单或面板，并保留已选范围和已应用筛选状态。
- 浮层按可用空间调整位置与内容滚动，标题、关闭入口及必要操作可访问。

## 大字体与缩放

- 在浏览器100%、150%、200%缩放下检查页面；150%是中间检查点，不能代替200%文字放大要求。不得在视口变窄时反向缩小字号抵消用户放大。参见 [文字放大](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)。
- Windows125%／150%系统缩放等目标配置另测；使用 CSS px 判断空间，不将系统倍率再乘到 Token。系统字体变大时，保留标签、错误和操作的完整可访问性。
- 容器采用内容撑开与最小高度，避免固定高度裁掉文字。按钮按组件规则保持标签单行，必要时加宽或把低频操作移至菜单；多行说明允许增加容器高度。
- 表单由多列改为单列；工具栏重排，导航可折叠，浮层限制到可用视口并允许内容滚动；关键操作保持可达。
- 检查长页面在320 CSS px宽度的重排（如1280宽窗口400%缩放）；需要二维关系的表格／图表可局部双向滚动，周围标题、搜索和分页仍重排。该检查不等于承诺完整手机产品体验。参见 [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。
- 验收：内容不重叠／裁切，文字可读，焦点不被固定区域遮挡，主操作与错误可访问；记录浏览器、缩放、视口、所测页面和未通过项。

## 无障碍

### 对比度与状态

- 普通文字与背景的对比度至少 4.5:1；大文字至少 3:1。大文字按 WCAG 定义为至少 18pt，或至少 14pt 粗体，不能仅按“标题”角色判断。装饰、标识及不可用控件等例外按标准适用范围判断。参见 [WCAG 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。
- 检查实际前景、背景、字号和交互状态；采用 Token 不等于自动满足对比度要求。
- 默认浅色 UI 使用已定义 Token；焦点、文字、图标与必要边界保持可辨识。完整深色 UI 参数未提供时不自行反色；代码区按其专用浅／深色表使用。
- 重要状态同时使用文字、图标或形状，不只依赖颜色。
- 对比度不满足时，检查用途和配置，选择适用的既有 Token；无法满足时记录冲突，不局部修改同名 Token 或直接声明合规。

复杂组件逐项键盘路径与 ARIA 属性见 [键盘与 ARIA](<键盘与焦点.md>)。

### 键盘与焦点

- 可操作入口支持键盘访问；复合控件使用与语义匹配的方向键、Enter、Space 等交互，Tab 顺序符合阅读与任务顺序。
- 焦点清晰可见，不被固定导航、浮层或滚动容器遮挡。
- 模态对话框及模态抽屉打开时将焦点移入，焦点保持在模态区域内；关闭后返回触发元素或合理的后续位置。高危确认按组件规则将初始焦点置于取消操作。参见 [模态对话框焦点规则](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。
- 非模态抽屉允许在页面与抽屉间切换，不限制焦点只能停留在抽屉内。
- 下拉菜单、选择器和交互气泡按各自语义处理焦点，不对所有浮层使用相同的焦点移动策略。
- Tooltip 不接收焦点；焦点保留在触发元素。需要操作内容时使用相应交互气泡。参见 [Tooltip 焦点规则](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/)。
- 可取消浮层支持 Escape 关闭；关闭当前层后恢复合理焦点。
- 主要、危险和确认操作不只依赖鼠标悬停发现；悬停提示提供键盘可访问方式。

### 可读名称与语义

- 图标按钮提供可读名称，表单控件具有明确标签；占位文字不替代标签。
- 必填、禁用、只读、选中、展开及校验状态在语义上与视觉一致。
- 错误信息与对应字段关联，说明原因及修正方式。
- 表格保留列头、行选择、排序、筛选和分页的可理解语义。
- 加载完成、提交结果和错误等必要状态变化可被辅助技术获知；避免高频刷新造成重复播报。
- 有信息含义的图片提供文字替代，纯装饰图形避免产生无意义朗读。

### 动效

- 动效用于反馈、过渡和状态表达，避免装饰性吸引注意。
- 响应用户的减少动态效果偏好，降低或关闭非必要动画，并保留可理解的状态反馈。
- 加载、展开、切换和刷新避免造成页面大幅跳动。

## 国际化与文案弹性

I18n Key 映射、可运行示例、RTL 矩阵与数字／日期口径见 [国际化](<国际化.md>)。

### 文案长度

- 预留翻译后约 40% 的长度增长空间作为初步检查，并以实际目标语言验证；固定比例不作为容纳所有语言的保证。
- 按组件规则选择换行、截断或完整内容查看方式。按钮和页签不因长文案折行或缩小字号；多选标签可按组件规则换行。
- 长标签或多语言表单优先使用标签在上、控件在下的布局。
- 优先改写为清晰、简短且不丢失业务含义的文案；截断后保留完整内容的可访问方式。
- 文案存放于可替换的语言资源中，避免无法独立翻译的拼接片段或生僻缩写。

### 格式与方向

- 数字、单位、日期、时间、货币和百分比采用项目国际化能力或标准 Intl 格式化，并保持同一语境下口径一致。
- 明确日期时间的时区和精度，按业务处理夏令时与不可选时段；显示格式与解析规则一致。
- RTL 场景检查起点／终点、图标与文字顺序、间距及方向性图标，避免只用固定左右位置表达逻辑。
- 不盲目镜像数字、图表或非方向性图标，按内容语义检查。
- 长语言及 RTL 环境下，表格、表单、筛选器和分页保留必要的操作区域。

## 极端输入与数据

| 场景 | 处理规则 |
| --- | --- |
| 空输入、无数据 | 提供明确的空状态、输入说明或校验提示；按 [内容状态](<内容状态.md>) 区分首次、零数据、无结果、无权限及失败 |
| 超长输入 | 输入框实时计数，超过最大字数仍允许继续输入并提示超限；提交校验遵循业务要求，不静默截断 |
| 超长展示内容 | 按组件使用截断、换行、滚动或详情查看，保证完整信息有访问路径 |
| 大量数据 | 按任务选择分页、筛选、折叠、摘要或虚拟滚动，保持选择、数量和操作范围可理解 |
| 异常字符、非法格式 | 在对应字段附近说明格式要求和修正方法，不吞掉输入或统一静默改值 |
| 缺少权限或上下文 | 说明缺少的条件及适用的下一步操作，不留下不可理解的空白区域 |
| 边界值 | 数字、跳页、日期和范围控件分别遵循其上下限、精度及超范围处理规则 |

## 完成检查

- 目标视口、窄窗口及缩放情况下，无关键内容或操作被遮挡。
- 主题与密度配置正确，未额外等比缩放全部控件。
- 主要流程可通过键盘完成，焦点可见且位置合理。
- 标签、错误、状态及表格语义可理解，对比度经过实际组合检查。
- 长文案、目标语言、空数据、超长输入及边界值处理清晰。
- 本文件为基础检查规则；未经完整评估，不声明整页或产品已符合全部 WCAG 要求。

## 不要

- 不要为适配窄屏删除必要状态、标签、校验信息或主操作。
- 不要用 viewport width 缩放字体，或以统一缩放代替布局调整。
- 不要移除可见焦点，或让焦点进入无法退出的非模态区域。
- 不要把所有浮层都当作模态对话框处理。
- 不要只靠颜色、悬停或无说明的纯图标表达关键含义。
- 不要用占位文字替代标签或实际错误反馈。
- 不要因翻译或异常输入使按钮组错位、内容重叠或操作区无法访问。
- 不要吞掉用户输入后没有反馈，或在服务不可用时仍表现为正常可操作。
